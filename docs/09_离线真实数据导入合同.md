# 09 离线真实数据导入合同

> 风险提示: 这条通道只负责把外部真实数据变成可审计的本地研究缓存。它不会连接券商,不会生成真实 broker 指令,也不能证明策略未来会赚钱。

## 适用场景

当 AKShare 或外部行情接口因为网络、权限、代理或供应商限制不可用时,可以从券商终端、数据商或你自己的数据管道导出 CSV,再通过本项目的离线合同进入同一套研究、审计、模拟盘和 LLM review 流程。

这条流程的核心原则是:

```text
先校验 CSV 合同 -> 再写入 SQLite 缓存 -> 再跑 real_data_bootstrap/data_audit -> 最后才允许研究流水线使用
```

`csv_validation` 通过只代表文件格式和基础质量满足导入要求。后续的真实数据门、覆盖率审计、稳健性测试和人工审批仍然拥有最终裁决权。

## 文件合同

`bars.csv` 是必需文件:

```text
symbol,date,open,high,low,close,volume,amount
```

推荐同时准备:

```text
stock_info.csv: symbol,name,exchange,list_date,delist_date,industry,is_st
fundamentals.csv: symbol,date,pe_ttm,pb,roe,market_cap,turnover_rate
calendar.csv: date,is_open
suspensions.csv: symbol,date,is_suspended
index_constituents.csv: index_code,date,symbol
```

字段约定:

- `symbol`: 6 位 A 股代码,例如 `600001`、`000001`。
- `date`: ISO 日期,例如 `2026-06-05`。
- `open/high/low/close`: 复权口径应与配置一致,默认 `qfq`。
- `volume`: 成交量。
- `amount`: 成交额。缺失时 importer 会填 0,但 validator 会给 WATCH。
- `is_st`: 0/1,用于 ST 风险识别。
- `is_open`: 1 表示开市交易日,0 表示非交易日。
- `is_suspended`: 1 表示当日停牌,用于 paper 拒单和人工目标组合风险标记。
- `index_code`: 指数或研究股票池代码,例如 `000906`; 用于复现 point-in-time 股票池。

导入器会兼容常见券商/数据商导出格式:

- 股票代码可写成 `600001.SH`、`000001.SZ`、`SH600001`、`SZ000001`,导入时会规范为 6 位代码。
- 指数代码可写成 `000906` 或 `SH000906`,导入时会规范为 `000906`。
- 日期可写成 `YYYY-MM-DD` 或 `YYYYMMDD`。
- 常见中文列名如 `证券代码`、`交易日期`、`开盘价`、`收盘价`、`成交量`、`成交额`、`证券简称`、`是否停牌` 会自动映射到标准字段。

如果拿到的是券商或数据商导出的原始日线 CSV,先把它规范成标准 `bars.csv`:

```powershell
.\.venv\Scripts\python.exe examples\normalize_vendor_bars.py `
  --input "<raw-vendor-bars.csv>" `
  --output-dir data_exports `
  --encoding auto `
  --start 2024-06-03 `
  --end 2026-06-05 `
  --min-symbols 300
```

Use `--encoding auto` for typical GBK/GB18030 broker exports. The raw-bars
normalizer accepts common English and Chinese OHLCV aliases, including
`code`/`symbol`, `代码`, `证券代码`, `股票代码`, `date`/`trade_date`,
`日期`, `交易日期`, `开盘`, `开盘价`, `最高`, `最高价`, `最低`,
`最低价`, `收盘`, `收盘价`, `成交量`, `成交量(股)`, `成交量(手)`,
`成交额`, `成交金额`, `成交额(元)`, and `成交金额(元)`.

输出:

- `data_exports/bars.csv`
- `data_exports/vendor_bars_normalization.json`
- `data_exports/vendor_bars_normalization.md`

`vendor_bars_normalization.json/md` also records the raw input file version:
`input_path`, `raw_sha256`, `raw_size_bytes`, and `raw_modified_at_utc`.
This is raw vendor file traceability; it is separate from the normalized CSV
batch `dataset_fingerprint`.

这个步骤只做字段映射、代码/日期规范化、基础 OHLCV 预检和输出合同格式。它不等于 source QA、CSV validation、缓存导入、策略通过或实盘许可。规范化后仍必须继续运行 import doctor、CSV validation、offline intake、bootstrap 和数据审计。

如果你本机已经安装通达信并有 `vipdoc` 日线文件,可以先把 `.day` 文件转换成标准 `bars.csv`:

```powershell
.\.venv\Scripts\python.exe examples\convert_tdx_day.py `
  --input-dir "<tdx-vipdoc-or-lday-dir>" `
  --output-dir data_exports `
  --start 2024-06-03 `
  --end 2026-06-05
```

常见输入目录类似 `C:\new_tdx\vipdoc`、`C:\new_tdx\vipdoc\sh\lday` 或 `C:\new_tdx\vipdoc\sz\lday`。转换器只读取本地文件,会写出 `bars.csv`、轻量 `stock_info.csv`、`calendar.csv` 以及 `tdx_day_export.json/md`。复权口径、许可范围、导出时间和人工复核仍必须写入 `data_source_qa_answers.json`。这类 `.day` 数据只足够优先验证 `price_volume_defensive` 这类 OHLCV-only 候选; 价值、质量等 PIT 财务因子仍需要单独的可信数据源。

## 导入前校验

使用 recent 配置的日期窗口做校验:

```powershell
.\.venv\Scripts\python.exe examples/validate_research_csv.py `
  --bars-csv data_exports\bars.csv `
  --stock-info-csv data_exports\stock_info.csv `
  --fundamentals-csv data_exports\fundamentals.csv `
  --calendar-csv data_exports\calendar.csv `
  --suspensions-csv data_exports\suspensions.csv `
  --index-constituents-csv data_exports\index_constituents.csv `
  --start 2024-06-03 `
  --end 2026-06-05 `
  --min-symbols 300 `
  --output-dir results\import\recent_csv_validation
```

输出:

- `csv_validation.json`
- `csv_validation.md`

每个文件都会记录 `sha256`、大小和 UTC 修改时间,整批数据会记录 `dataset_fingerprint`。后续 `data_import.json` 和 SQLite 缓存的 `research_metadata` 会保存同一个 fingerprint,用于证明某次研究到底使用了哪一批离线数据。

When guarded intake is run with `--raw-bars-csv`, `data_import.json` and SQLite
`research_metadata` also retain `raw_vendor_bars_*`,
`vendor_bars_normalization_status`, and `vendor_bars_normalization_report`.
The intended audit chain is: raw vendor CSV -> normalized `bars.csv` -> CSV
`dataset_fingerprint` -> cache metadata -> run manifest.

When guarded intake imports CSV files produced from TDX `.day` conversion, it
also retains `tdx_day_export_report`, `tdx_day_export_sha256`,
`tdx_day_input_dir`, symbol/row counts, and export date bounds in
`data_import.json`, SQLite `research_metadata`, and the run manifest. The
capital-goal status report checks this chain as `tdx_day_traceability`; missing
or mismatched TDX export evidence blocks strategy search.

校验会检查:

- 必需列是否存在。
- 日期和数值是否能解析。
- OHLC 是否自洽。
- 重复 `symbol/date`。
- 非正成交量或成交额。
- 股票数量是否低于目标。
- 开市日历和 K 线覆盖是否明显不一致。
- `stock_info` 和 `fundamentals` 是否覆盖 `bars` 中的股票。
- `suspensions` 和 `index_constituents` 是否引用了 `bars` 外的股票。

如果 CSV 是 GBK 编码:

```powershell
.\.venv\Scripts\python.exe examples/validate_research_csv.py --bars-csv data_exports\bars.csv --encoding gbk --output-dir results\import\csv_validation
```

## 写入研究缓存

校验没有 BLOCK 后,再导入 SQLite:

```powershell
.\.venv\Scripts\python.exe examples/import_research_csv.py `
  --cache .\data_cache\research_recent.db `
  --bars-csv data_exports\bars.csv `
  --stock-info-csv data_exports\stock_info.csv `
  --fundamentals-csv data_exports\fundamentals.csv `
  --calendar-csv data_exports\calendar.csv `
  --suspensions-csv data_exports\suspensions.csv `
  --index-constituents-csv data_exports\index_constituents.csv `
  --validate `
  --start 2024-06-03 `
  --end 2026-06-05 `
  --min-symbols 300 `
  --output-dir results\import\recent_csv
```

输出:

- `data_import.json`
- `data_import.md`
- `csv_validation.json`
- `csv_validation.md`

如果内置校验返回 BLOCK,导入命令会在写入缓存前停止。WATCH 可以继续导入,但 `data_import.json` 也会保留 WATCH 证据,后续 bootstrap 和 data audit 仍可能阻止研究升级。

受控 intake 前可以先生成一张离线数据包就绪卡。它合并 source QA、CSV inventory、模板行检测和 import doctor,输出包级 PASS/WATCH/BLOCK:

```powershell
.\.venv\Scripts\python.exe examples\run_offline_data_package.py `
  --data-dir data_exports `
  --config config\research_recent.yaml `
  --output-dir results\first_million `
  --source-qa-answers data_exports\data_source_qa_answers.json `
  --as-of 2026-06-08 `
  --min-symbols 300
```

输出:

- `offline_data_package.json`
- `offline_data_package.md`

如果不想手动拆分这些步骤,可以使用受控 intake 命令。它会按顺序运行 doctor、CSV validation、import 和 bootstrap,并在任一 BLOCK 时停止:

```powershell
.\.venv\Scripts\python.exe examples/run_offline_data_intake.py `
  --raw-bars-csv "<raw-vendor-bars.csv>" `
  --data-dir data_exports `
  --config config/research_recent.yaml `
  --output-dir results\import\offline_intake `
  --source-qa-answers data_exports\data_source_qa_answers.json `
  --source-vendor "<vendor-or-broker>" `
  --source-terminal "<terminal-name>" `
  --source-operator "<operator>" `
  --source-exported-at "<local-time>" `
  --source-price-adjustment qfq `
  --source-price-adjustment-evidence "<evidence>" `
  --source-license-evidence "<evidence>" `
  --source-point-in-time-evidence "<evidence-or-non-pit-note>" `
  --source-reviewed-by "<name>" `
  --source-reviewed-at "<date>" `
  --as-of 2026-06-08 `
  --min-symbols 300 `
  --min-trading-days 240
```

输出:

- `offline_data_intake.json`
- `offline_data_intake.md`
- 通过前置门时还会写出 `csv_validation`、`data_import` 和 `real_data_bootstrap` 产物。

如果传入 `--raw-bars-csv`,受控 intake 会先运行 vendor bars normalization 并写出 `vendor_bars_normalization.json/md`; normalization 为 BLOCK 时会在写入缓存前停止。即使 normalization 通过,source QA、doctor、CSV validation、bootstrap 仍然照常拥有硬门。

For raw vendor CSV intake, verify that `vendor_bars_normalization.json.raw_sha256`
matches `data_import.json.metadata.raw_vendor_bars_sha256` and SQLite
`research_metadata.raw_vendor_bars_sha256` after import.

如果同时传入 `--source-*` 字段,intake 会从这些显式证据写出 `data_source_qa_answers.json` 并立即审查。字段缺失、占位符或弱证据会 BLOCK,不会继续写缓存。不要把示例里的 `<...>` 原样当作证据。

## 安全边界

- CSV 校验不调用网络。
- CSV 导入不连接真实券商。
- `manual_trade_sheet.csv` 只供人工参考,不是订单; ST、退市、停牌和涨跌停标记只用于暴露人工复核风险,不能自动生成 broker 指令。
- LLM 只能写 advisory narrative,不能覆盖 deterministic gate。
- 任一 BLOCK 都应降级回 research/paper,不能推进 `micro_live_ready`。
