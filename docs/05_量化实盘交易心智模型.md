# 05 量化实盘交易心智模型

> 风险提示: 本文是系统建设框架,不是投资建议。历史回测、LLM 分析和模拟盘结果都不能保证未来收益。

量化实盘不是“让机器预测涨跌”,而是把交易拆成一套可复现、可审计、可暂停的决策系统。你需要同时扮演三个角色:

- 研究员: 提出市场假设,验证它是否有统计证据。
- 工程师: 让数据、回测、下单、日志和报警稳定运行。
- 风控官: 设定什么情况下必须停手,并让系统强制执行。

## 一句话模型

```text
目标约束 -> 市场假设 -> 数据证据 -> 策略规则 -> 回测检验
        -> 模拟执行 -> 小额实盘 -> 监控复盘 -> 迭代或下线
```

任何一步没有证据,都不能跳到下一步。LLM 可以帮助你写研究备忘录、审查遗漏、生成实验清单,但不能越过风控门直接下单。

## 第一层: 目标与约束

先回答这些问题:

- 资金用途: 这是学习资金、长期投资资金,还是短期投机资金?
- 最大可承受亏损: 账户亏损多少必须停止?
- 最大回撤: 策略从高点回撤多少必须降仓或下线?
- 交易频率: 日频、周频、月频,还是日内?
- 市场范围: A 股、ETF、港股、美股、期货、数字资产?
- 杠杆边界: 是否允许融资、期货保证金、期权?
- 操作权限: 是完全自动,还是每次调仓人工确认?

新手默认答案应保守:

```text
低频、无杠杆、只做多、纸面交易先行、小额实盘后置、人工确认调仓。
```

## 第二层: 市场假设

策略不是指标堆叠,而是一句可被证伪的假设。例如:

- 动量: 过去一段时间表现强的股票,短期内可能继续表现强。
- 低波动: 低波动股票可能在风险调整后表现更稳。
- 价值: 便宜资产在长期可能获得估值修复。
- 质量: 盈利质量更高的公司可能更能穿越周期。
- 流动性: 流动性太差会吞噬纸面收益。

好假设要有三点:

- 可解释: 为什么这个现象可能存在?
- 可测量: 用哪些字段和公式表达?
- 可失效: 什么证据出现时说明它不再成立?

## 第三层: 数据心智

量化系统的第一风险不是模型错,而是数据错。实盘前至少检查:

- 价格是否复权一致。
- 是否包含退市、停牌、ST、涨跌停。
- 是否有未来函数,例如用到了调仓日之后才知道的财报。
- 是否有幸存者偏差,例如只看今天仍存在的股票。
- 是否有缺失值、异常成交量、重复 K 线。
- 回测和实盘使用的数据口径是否一致。

原则:

```text
宁可少用数据,也不要使用不知道含义的数据。
```

## 第四层: 策略规则

策略必须能被写成明确规则:

```text
股票池: 排除 ST、停牌、上市不足 N 天、无价格数据。
信号: 多因子标准化后取综合分最高的前 N 只。
调仓: 每月第一个交易日调仓。
仓位: 等权,单票不超过 5%。
交易: A 股 T+1,100 股整数倍,考虑手续费、印花税、滑点。
退出: 不在目标池则卖出,遇停牌或跌停则延迟。
停机: 回撤超过阈值后不再开新仓。
```

如果规则无法写清楚,就还不是量化策略。

## 第五层: 回测可信度

一份可考虑进入模拟盘的回测,至少要回答:

- 收益是否扣除了交易成本和滑点?
- 最大回撤是否可承受?
- 夏普是否来自少数几次极端行情?
- 换手率是否过高?
- 拒单、涨跌停、停牌是否被模拟?
- 样本外表现是否仍然合理?
- 参数轻微变化后是否仍然有效?
- 因子 RankIC 是否长期为正?

不要只看最终收益。实盘中更重要的是:

```text
回撤、换手、成交质量、容量、失效条件。
```

## 第六层: 模拟盘

模拟盘不是为了证明会赚钱,而是为了证明系统不会乱来:

- 行情更新是否稳定。
- 调仓日是否正确。
- 订单数量是否符合 100 股整数倍。
- 现金是否可能变负。
- 停牌、涨停、跌停是否正确拒单。
- 日志是否能解释每笔交易。
- 系统异常时是否停止交易。

至少连续运行 4-8 周,并把每次异常写入复盘。

## 第七层: 小额实盘

小额实盘的目标不是赚钱,而是验证真实市场摩擦:

- 实际成交价和回测假设差多少。
- 滑点是否随行情波动扩大。
- 券商 API 是否稳定。
- 下单时间是否会错过成交窗口。
- 实盘心态是否会干扰执行。

第一阶段只允许小额、无杠杆、人工确认。每次提高资金前,都要重新过一遍审查门。

## 第八层: 风控优先级

风控优先级高于策略信号:

```text
数据异常 > 账户异常 > 回撤停机 > 仓位限制 > 策略信号 > 执行优化
```

常用硬规则:

- 单票最大仓位。
- 行业或主题最大仓位。
- 单日最大亏损。
- 累计最大回撤。
- 单次调仓最大换手。
- 单日最大下单次数。
- 连续异常自动停机。
- 任何 LLM 输出都不能直接越权下单。

## 第九层: 复盘

每次运行都要留下证据:

- 当时的配置。
- 数据版本。
- 目标持仓。
- 实际订单。
- 成交明细。
- 拒单原因。
- 每日净值。
- 策略假设是否仍成立。
- 下一轮实验要验证什么。

复盘不是写感想,而是降低下一次犯错的概率。

## 第十层: LLM 在系统里的位置

LLM 适合做:

- 把回测报告翻译成人话。
- 根据指标提出风险问题。
- 检查是否缺少样本外、参数扰动、压力测试。
- 生成实验计划。
- 总结交易日志和异常。
- 帮你写研究备忘录。

LLM 不适合直接做:

- 直接决定买卖。
- 绕过回测。
- 绕过风控。
- 在没有数据证据时给确定性判断。
- 自动连接券商并发单。

推荐架构:

```text
Quant Engine 产生证据
        |
Deterministic Gate 先给 PASS/WATCH/BLOCK
        |
LLM Reviewer 只做解释、追问、实验建议
        |
Human Approval 决定是否进入下一阶段
        |
Broker 接口按硬风控执行
```

## 实盘发布门

可以把策略分成四个阶段:

```text
research   只研究,不能连券商。
paper      模拟盘,不能真实下单。
micro_live 极小资金实盘,必须人工确认。
live       扩大资金,仍需版本化审查。
```

升级条件:

- `research -> paper`: 回测完整,无明显未来函数,指标可解释。
- `paper -> micro_live`: 模拟盘稳定运行,拒单和异常可解释。
- `micro_live -> live`: 实盘滑点、执行、回撤都在预设范围内。
- `live -> larger_live`: 新资金也要当成新版本重新审批。

降级条件:

- 数据源异常。
- 回撤触发阈值。
- 实盘滑点显著高于假设。
- 策略收益来源无法解释。
- LLM 或人工复盘发现关键证据缺失。

这就是你要建立的核心心智: 不追求一次看对,而是建立一套持续少犯大错的机器。
