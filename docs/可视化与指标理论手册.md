# 可视化与指标理论手册

这份手册解释研究报告里的图表和指标**为什么重要、应该怎样阅读、什么时候不能
相信它们**。它补充 [03 如何阅读研究报告](03_如何阅读研究报告.md) 的字段说明，
不把历史回测包装成收益承诺。

> 风险提示：历史回测、模拟盘和图表都不代表未来收益。本项目只用于研究与仿真，
> 不连接券商、不自动下单；任何图表都不能替代数据审计、样本外验证和人工审批。

## 1. 先生成一张离线仪表盘

研究报告目录通常位于 `results/research/<时间戳>/`。在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe examples\build_report_dashboard.py `
  --report-dir results\research\<时间戳> `
  --output results\research\<时间戳>\dashboard.html
```

省略 `--output` 时，文件默认写到报告目录的 `dashboard.html`；加 `--open` 可以尝试
用默认浏览器打开。仪表盘只读取本地 `summary.json`、CSV 和可选审查 JSON，CSS 与
SVG 全部内嵌，因此可以在断网时双击查看，也不会向外部网站发送报告内容。

报告目录必须有 `summary.json`。`data_audit.json`、`llm_review.json`、各类 CSV 或
目标状态文件缺失时，页面会显示“不可用”；未知或损坏的门状态一律按 `BLOCK` 展示。
这是一种安全降级，不是对策略的否定性结论。`results/research/20260712_064935/`
是历史 UI fixture，载荷含 `DEMO*` 标的，只能用来检查布局和容错，不能作为真实研究
证据。

## 2. 阅读顺序：先证据，再曲线，最后指标

建议按下面的顺序看，不要从“最高收益”开始挑结果：

```text
数据审计/研究门 → 净值与回撤 → 样本长度与样本外 → IC 与换手
                         ↓
                 拒单原因与执行约束
                         ↓
                 下一步实验或暂停
```

仪表盘顶部的 `RESEARCH-ONLY / NO BROKER / NO LIVE ORDERS` 是运行边界，不是营销
标签。绿色 KPI 只表示数值没有触发当前的提示阈值，不表示晋级或可交易。

## 3. 净值曲线：看复利过程，不只看终点

### 直觉

净值曲线是每天组合总资产的时间序列。终点相同的两条曲线，可能一条平稳增长，另一条
先腰斩再反弹；后者对资金和心理的要求完全不同。看曲线时先问：是否持续创新高？
亏损后多久恢复？收益是否只集中在一小段行情？

### 计算口径

`equity.csv` 的每一行是一个净值点。总收益为：

```text
total_return = final_equity / initial_equity - 1
```

仪表盘用折线展示原始顺序，并在点上保留日期和数值提示；长序列只做等距抽样以控制
HTML 大小，不改变 KPI 的来源。

### 怎么判断与陷阱

- 上升但锯齿很大，通常意味着回撤或换手风险被终点掩盖。
- 只有少数尖峰的曲线需要检查事件驱动、价格缺失和样本外覆盖。
- 负净值、非数值或缺失行不会被填成 0；它们会让对应图表显示不可用。

对应仪表盘：**净值曲线与回撤**。对应代码：`src/quantify/analytics/metrics.py`、
`src/quantify/analytics/dashboard.py`。

## 4. 最大回撤：决定能否承受，而不是决定好不好看

### 直觉

最大回撤回答“从过去某个峰值跌到后续谷底，最多损失了峰值的多少比例”。它比单纯的
波动更贴近资金使用体验，也直接关系到风控预算和是否能坚持执行。

### 计算口径

项目按每个时点的历史峰值计算：

```text
drawdown(t) = 1 - equity(t) / max(equity(截至 t))
max_drawdown = max(drawdown(t))
```

`summary.json` 中的 `max_drawdown` 是正比例（例如 `0.20` 表示 20%）。图表为了让
“向下”更直观，把回撤轨迹画成负百分比；两者表达的是同一件事。资金目标默认的
回撤预算在 `src/quantify/goal/planner.py` 中定义，候选筛选会把超预算视为扣分或阻断。

### 怎么判断与陷阱

- 不只看最大值，还看回撤持续时间和恢复速度。
- 小样本没有经历压力行情时，低回撤不能证明未来安全。
- 用调整参数把回撤剪掉，必须同时重跑冻结的样本外和稳健性实验。

对应仪表盘：**最大回撤轨迹**和“最大回撤” KPI。红色只是提醒超过展示阈值，最终
结论仍由确定性审查门给出。

## 5. 夏普比率：把收益放回风险背景

### 直觉

夏普比率衡量单位波动换来了多少超额收益。它适合比较同一口径下的策略，但不是概率、
也不是“每年一定赚多少”的承诺。

### 计算口径

项目默认无风险年化利率为 0。先求每日收益，再按 252 个交易日年化：

```text
daily_return = equity(t) / equity(t-1) - 1
excess = daily_return - risk_free_rate / 252
sharpe = mean(excess) / std(excess) × √252
```

样本不足或波动为零时，代码返回 0，而不是伪造无穷大。候选规划把 `0.8` 作为值得
警惕的最低观察线；这只是研究提示阈值，不是通用行业标准。

### 怎么判断与陷阱

- 高夏普可能来自过少的交易日、平滑估值或未来信息泄漏。
- 非正态收益、极端跳空和交易成本会让夏普失真；要同时看回撤、换手和压力测试。
- 不同频率、不同无风险利率或不同缺失值处理的夏普不能直接横比。

对应仪表盘：**夏普比率** KPI。读到绿色时仍需回到数据审计和样本外门。

## 6. 年化收益与总收益：不要把短样本外推成长期能力

### 计算口径

项目使用几何年化，假设每个净值点代表一个交易日：

```text
n_periods = 净值点数量 - 1
annualized_return = (final / initial) ** (252 / n_periods) - 1
```

当调用方另行提供初始现金时，初始现金会作为额外的起点参与计算，但 `n_bars` 仍记录
报告 CSV 的净值点数。总收益只描述这一次区间，年化收益是把区间几何增长率换算到一年，
两者都不等于未来预期。

### 怎么判断与陷阱

- 只有几周的 100% 总收益，年化后会被指数放大，统计意义很弱。
- 年化收益高但回撤和换手也高，可能只是承担了不可接受的风险或摩擦成本。
- 必须核对 `in_sample_end`、`out_sample_start` 和 walk-forward 窗口，不要把训练期
  结果称为样本外。

对应仪表盘：**总收益**、**几何年化** KPI；样本点数在 KPI 下方作为提醒。

## 7. 因子 RankIC：信号是否有排序信息

### 直觉

RankIC 不问“今天买哪一只一定涨”，而问“今天因子排序靠前的标的，下一期是否倾向于
获得更高收益”。它评价的是排序信息，不是策略最终盈亏。

### 计算口径

`research/engine.py::_compute_factor_ic` 将某日因子分数的秩与**次日收益率的秩**做
Spearman 相关，结果写入 `factor_ic.csv` 的 `rank_ic` 列。仪表盘正值画绿色、负值画
红色，并保留每根柱的日期。

### 怎么判断与陷阱

- 长期平均略为正且不同窗口方向一致，比一次极端正值更可信。
- IC 接近 0 说明该排序在当前样本没有明显预测力；负值可能是方向反了，也可能是
  样本噪声，不能只靠调符号解决。
- 先检查横截面数量、缺失值、行业暴露和多重检验，再谈因子是否有效。

对应仪表盘：**因子 RankIC**。图表只展示观察，不会把 IC 自动升级为 PASS。

## 8. 换手率：纸面收益要扣掉摩擦

### 直觉

换手率表示组合有多频繁地改变。高换手会带来佣金、印花税、滑点、涨跌停无法成交和
信号延迟；净值曲线看似漂亮，成本一加可能完全不同。

### 计算口径

优先读取 `turnover.csv` 的 `turnover_pct`（小数比例，例如 `0.05` = 5%）。仪表盘
对它求平均并按百分比展示；如果只有 `turnover` 金额，会显示原始金额图，但不会冒充
换手率，也不会生成平均换手 KPI。

### 怎么判断与陷阱

- 看平均值、最大尖峰和调仓频率，而不是只看平均值。
- 研究时应做更高佣金/滑点的压力测试；成本假设必须写进报告证据。
- 用更密集调仓去追逐短期 IC，往往会把预测微弱的收益交给市场摩擦。

对应仪表盘：**换手率（turnover_pct）**。高换手的橙色柱是成本预警，不是交易建议。

## 9. 胜率与盈亏比：赢得多不等于赚得多

### 计算口径

项目对同一标的的 LONG/EXIT 成交按 FIFO 队列配对。每个完整卖出回合计一次；扣除
佣金和印花税后的卖出净额大于对应买入成本才算 win：

```text
win_rate = 盈利完整回合数 / 完整买卖回合数
```

部分成交也会按匹配数量计算，但没有配对买入的退出不会凭空增加胜率。

### 怎么判断与陷阱

- 70% 胜率仍可能因少数大亏而总体亏损；请同时看平均盈利、平均亏损和最大回撤。
- 不同策略的持仓周期不同，胜率不能脱离时间和成本比较。
- 若 `trades.csv` 与 `summary.json` 的回合数对不上，应先停下检查报告生成和成交日志。

当前仪表盘展示胜率 KPI 和完整回合数，但不替代逐笔成交审计。

## 10. T+1 与拒单：执行约束是证据的一部分

### 为什么会拒单

`orders.csv` 的 `status=rejected` 不是系统“坏了”的同义词。常见 `reason` 包括：

- `t_plus_one`：当天买入的股票不能当天卖出；
- `not_buyable`、涨跌停或停牌：价格触及执行限制；
- `cash`：现金不足；
- `no_price`：缺少可用价格。

仪表盘按拒单原因计数，并用 `拒单率 = rejected / all orders` 生成提示。缺少订单文件
时显示不可用，不把“没有记录”误读成 0% 拒单。

### 怎么判断

拒单率高可能暴露目标权重、资金、交易日历或数据质量问题；拒单率很低也不一定好，
有可能策略根本没有发出订单。应把原因分布和成交率、换手、现金曲线一起看。

## 11. PASS / WATCH / BLOCK：门是决策边界，不是颜色游戏

- **PASS**：当前合同和证据满足该阶段的确定性条件。
- **WATCH**：有可解释的缺口或风险，需要补证据、复核或继续观察。
- **BLOCK**：缺少关键证据、检测到硬风险或输入无法验证；不能靠图表、LLM 或手工
  解释绕过。

数据审计门来自 `data_audit.json`，研究审查门来自 `llm_review.json` 的确定性结果；
LLM 的文字只能帮助解释和提出下一项实验，不能把 BLOCK 改成 PASS。仪表盘对未知、缺失
或损坏的状态默认显示 BLOCK，并在“输入与证据状态”里标注原因。

最重要的顺序是：

```text
BLOCK → 找到具体缺失证据 → 补数据/重跑实验 → 重新审查
  ↑                                                   ↓
  └────────────── 不能用漂亮曲线跳过 ────────────────┘
```

## 12. 仪表盘板块与源文件对照

| 板块 | 主要源文件 | 读法 |
| --- | --- | --- |
| 数据审计/研究审查徽章 | `data_audit.json`、`llm_review.json` | 先确认状态可验证，再读指标 |
| KPI 卡片 | `summary.json`、`turnover.csv`、`orders.csv` | 只作定位风险的摘要 |
| 净值与回撤 | `equity.csv` | 看路径、恢复和压力 |
| RankIC | `factor_ic.csv` | 看方向、持续性和样本量 |
| 换手 | `turnover.csv` | 看成本暴露和尖峰 |
| 拒单分布 | `orders.csv` | 看 A 股执行约束是否被尊重 |
| 持仓快照 | `positions.csv` | 检查集中度、权重和最后状态 |

## 13. 读完检查清单

- [ ] 风险提示和 `RESEARCH-ONLY` 边界仍在页面顶部。
- [ ] `data_audit.json`、样本窗口和数据来源已核对；没有把 UI fixture 当真实证据。
- [ ] 净值、最大回撤、恢复时间和样本外窗口一起看过。
- [ ] RankIC 的长期方向、换手成本和拒单原因已解释。
- [ ] 缺失或未知文件显示为不可用/BLOCK，而不是 0 或绿色。
- [ ] 任何下一步都回到确定性门、稳健性实验和人工审批，没有自动下单路径。
